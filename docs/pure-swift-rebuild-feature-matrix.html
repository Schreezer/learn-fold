Learnfold rebuild decision

Pure Swift keeps the learning studio. It drops the remote agent platform.

A no-Rust, no-built-in-Codex rebuild can still create, edit, sync, and generate personal courses with Apple Foundation Models. What disappears is the generic Codex/Hermes runtime: remote computers, coding-agent threads, terminal, SSH, approvals, and multi-agent orchestration.

Keep the product core Course library, plans, lessons, editor, sources, local recovery, and iCloud.
Rewrite the glue Swift state, streaming conversations, tool dispatch, and Apple-platform projections.
Remove the agent shell Codex app-server, UniFFI, Rust store, Hermes/Alleycat, SSH, terminal, and generic coding tools.

Feature-by-feature outcome

“Keep” means the capability already has a Swift/Apple-native foundation. “Rewrite” means the product feature can remain, but its current Rust-facing control path cannot.

Will have

My Courses library

Course cards, progress, continue-learning, course detail, and the learning-path tree stay as native SwiftUI product surfaces.

Already lives in SwiftUI + local course models.
Will have

Guided course creation

Start from a topic, run the learner diagnostic, review a proposed course plan, explicitly approve it, and progressively generate lessons.

AppleCourseAgent already implements the Apple-native path.
Will have

Apple intelligence providers

Apple On-Device and Apple Private Cloud Compute can remain the default course agents, including provider switching and context compaction.

Uses Foundation Models directly from Swift; no Codex loopback required.
Will have

Native course editor

Editable pages, course structure, autosave, save recovery, revision checks, selection highlights, and “Ask AI” discussions can remain.

NativeBlockEditor and CourseDocumentRepository are Swift packages/code.
Will have

Sources and attachments

Topic, link, file, PDF/text extraction, and photo intake can stay, along with bounded local staging and safe URL/download rules.

CourseSourceIngestion is a Swift actor using Foundation and PDFKit.
Will have

Local-first persistence

Course workspaces, drafts, protected plan approvals, pending edits, relaunch recovery, and legacy course import can remain on device.

The authoritative course repository is already native Swift/SQLite-backed.
Will have

iCloud course sync

Private CloudKit sync, checksummed generations, account isolation, conflict handling, and offline outbox behavior can remain.

CourseCloudSyncEngine is native Swift + CKSyncEngine.
Will have

Native look and accessibility

SwiftUI navigation, dark/light appearance, Dynamic Type, VoiceOver semantics, wallpapers, branding, and other visual polish are independent of Rust.

Presentation stays entirely Apple-platform code.
Rebuild in Swift

Course chat state

The learner-facing chat can stay, but thread snapshots, streaming status, interruption, hydration, retry, and draft reconciliation need a new Swift-owned store.

CourseExperienceStore currently mixes course state with AppModel/Rust thread state.
Rebuild in Swift

Course tool execution

Plan presentation and editor tools can remain, but the baseline should call Swift repository methods directly instead of Codex MCP/dynamic-tool transport.

Apple agents already prove the direct-call architecture.
Rebuild in Swift

Background generation recovery

Apple-model turns can keep durable progress and recovery, but Codex/Hermes-specific accepted-turn journals and multi-turn remote recovery should be replaced with one Swift lifecycle.

The learner promise stays; the runtime-specific implementation does not.
Optional later

Non-Apple model providers

A pure Swift URLSession/SSE provider client could add OpenAI-compatible APIs later, without bundling Codex or reintroducing Rust.

Not part of the clean baseline; it is a separate provider adapter.
Rebuild in Swift

Voice, Watch, Live Activities

The Apple UI shells may stay, but their task/thread projections and voice handoff currently depend on the shared runtime and must be redesigned around course sessions.

Platform code exists, but the data/control source is Rust-owned today.
Won’t have

Built-in Codex runtime

No on-device Codex app-server, Codex binary bootstrap, ChatGPT login bridge, API-key configuration for Codex, model catalog, or Codex thread management.

Explicitly removed with the Codex submodule and Rust client.
Won’t have

Hermes / Learnfold Link

No Telegram pairing flow, Alleycat encrypted remote transport, VPS-hosted Hermes runs, remote tool-result loop, or Hermes cold-launch recovery.

The current connection, transport, and session path is Rust-backed.
Won’t have

Remote computers and SSH

No Bonjour server discovery, SSH credentials/host trust, remote bootstrap, reconnect policy, port forwarding, or cross-server session dashboard.

These are core services of codex-mobile-client.
Won’t have

Terminal and local Unix runtime

No Ghostty-backed terminal session, iSH/proot environment, shell execution, filesystem mount runtime, or remote Alleycat terminal.

The present terminal backend and execution lifecycle are Rust-owned.
Won’t have

Generic coding-agent features

No approvals/sandbox controls, diffs, computer-use tool cards, subagents, saved generated apps/widgets, image-generation tools, or cross-server agent handoff.

Those surfaces consume Codex-compatible events and tool state.
Won’t have

Other agent runtimes

No Claude Code, OpenCode, Droid, Pi, Amp, Grok, Devin, or runtime catalog supplied by a connected app server.

They are runtime plugins, not native Learnfold course engines.
Won’t have

Android shared-core parity

The rebuild becomes an Apple-only product unless Android is separately reimplemented; there is no Rust core or UniFFI contract to share.

Pure Swift deliberately chooses the iOS product boundary.

Clean target architecture

A much smaller app graph, with the course—not the agent runtime—as the center of the product.

Experience SwiftUI course library · guided creation · lesson reader/editor · course chat
App state Swift Observation store · course drafts · streaming messages · recovery journal
Intelligence Apple On-Device · Apple Private Cloud Compute · optional pure-Swift API adapter later
Course data NativeBlockEditor · local SQLite/files · source ingestion · CloudKit sync
Build Xcode + Swift Package Manager + XcodeGen — no Cargo, UniFFI, generated bindings, or Rust static libraries

Entire setup removed

  • shared/rust-bridge/ and Cargo toolchains
  • shared/third_party/codex/ and Codex patches
  • UniFFI-generated Swift/Kotlin bindings
  • GeneratedRust staticlibs and XCFramework packaging
  • Rust/AppStore/AppClient bridge initialization
  • Rust-specific Make targets and cache stamps
Important: deleting Rust today will not leave a compiling app. The course UI is native, but the current root app and course conversation store still reference Rust-generated types. This is a focused rebuild of the app shell and state boundary, not just dependency cleanup.
Assumption used for this comparison: the new baseline is iOS-only, keeps Apple Foundation Models and CloudKit, keeps the current native course/editor experience, and intentionally removes all local/remote coding-agent infrastructure. “Won’t have” means absent from that clean baseline—not technically impossible to add later in pure Swift.
